§ The common thread

An LLM is great at deciding what to do — and the wrong tool for computing a number. So I split the two, and make the split enforceable.

The same architecture shows up in everything below: the model plans, picks tools, and explains itself in plain language — while deterministic code computes every price, score, and figure. A grounding guard sits in the middle: if the model ever states a number it didn't get from a tool, the answer is refused and the tool is called. That's the difference between an impressive demo and something a business can actually depend on.

Plans

The LLM decides what

Understands the request, chooses the right tools, handles multi-turn conversation, and explains the answer in human language.

Computes

The code decides how

Prices, scores, and retrieval ranking are computed by deterministic code — testable, repeatable, and auditable. No vibes.

Enforces

The guard makes it true

A grounding layer refuses any fact the model didn't source from a tool, and an eval framework turns "is it accurate?" into a number.
