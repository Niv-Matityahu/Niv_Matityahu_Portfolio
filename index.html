§ The common thread

An LLM is great at deciding what to do — and the wrong tool for computing a number. So I split the two, and make the split enforceable.

The same architecture shows up in everything below: the model plans, picks tools, and explains itself in plain language — while deterministic code computes every price, score, and figure. A grounding guard sits in the middle: if the model ever states a number it didn't get from a tool, the answer is refused and the tool is called. That's the difference between an impressive demo and something a business can actually depend on.

Plans

The LLM decides what

Understands the request, chooses the right tools, handles multi-turn conversation, and explains the answer in human language.

Computes

The code decides how

Prices, scores, and retrieval ranking are computed by deterministic code — testable, repeatable, and auditable. No vibes.

Enforces

The guard makes it true

A grounding layer refuses any fact the model didn't source from a tool, and an eval framework turns "is it accurate?" into a number.

01 ● Live in production Conversational commerce · Moveo AI

A WhatsApp sales & service agent for a national Israeli retailer

The retailer wanted customers to browse, get recommendations, and actually buy — inside WhatsApp, the channel they already live in. The hard constraint, and the whole reason this is difficult: an assistant that quotes real prices and stock and never invents either, running live for real customers.

What I built

  • Hybrid retrieval for product discovery — taxonomy expansion and SQL pre-filtering, then weighted fusion of BM25 + embeddings, then re-ranking, so the model is handed the right products, not just similar ones.
  • An orchestration layer with tool-calling and reliable state across multi-turn conversations — it remembers context without losing the thread.
  • Multi-stage output guardrails that ground every fact & price and strip hallucinated product names.
  • Live data integration with product, inventory & pricing feeds, with automated syncs keeping the catalog current.

Outcome

  • Shipped and live to real customers over WhatsApp.
  • Prices and stock stay grounded — no hallucinations.
  • Deployed on serverless AWS with push-to-main CI/CD.

03 ▶ Live demo · open source AI agent · solo build

An AI analyst that finds the US airports worth expanding

A conversational agent that ranks US airports for terminal-expansion investment — by chat or voice. The insight most takes miss: a fund only profits where capacity is choked, so size and growth alone shouldn't win. I encoded that thesis into a deterministic Expansion Opportunity Score, not the prompt.

How it works

  • Agent loop (Gemini / Claude) with 7 typed tools — it plans and narrates; code computes every number.
  • Choke-gated score: EOS = (Choke·45 + Demand·30 + Scale·25) × choke-gate, as outlier-robust national percentiles.
  • A grounding guard that refuses any figure the model didn't pull from a data tool — so it can't invent a number.
  • Built on public FAA · BTS · OurAirports data, with per-airport confidence flags.

Proof

  • Live, deployed, and usable right now on Streamlit.
  • 22 passing tests over the scoring core and tools.
  • Full design doc covering methodology, tradeoffs, and where AI is (and isn't) used.

04 ◆ Product · full-stack Personal finance + AI · solo build

FinWise — a personal-finance app with a grounded AI advisor

A full-stack finance assistant with a Hebrew, right-to-left interface: dashboard, transactions, budgets, forecasts — and a Claude-powered advisor you can actually ask about your own money. The same principle as the rest: the advisor is grounded, not guessing.

What I built

  • A single full-stack Next.js 15 / React 19 / TypeScript app in clean layers — UI, a single server endpoint, and framework-free business logic.
  • A grounded advisor: the server summarizes your real numbers and streams them to Claude as context, so it answers from your data — and the API key never leaves the server.
  • Rules engines for categorization, budgets, alerts, and end-of-month forecasting — all pure, testable TypeScript.
  • CI (lint + build on every push) and one-click Render deploy; designed so swapping mock data for a real bank API touches one file.

Why it matters

  • Shows the full stack: product, UX (incl. RTL), architecture, and a safely-integrated LLM.
  • Built to graduate from mock data to a live Open-Banking feed without a rewrite.

05 ◆ Research · open source B.Sc. final project · Azrieli College

SmartAssessor — an AI tutor that grades exercises, step by step

My degree's final project: a system that grades students' work and returns step-by-step corrections, not just a mark. The interesting part is the architecture — running a GPU language model without coupling the web app to a GPU.

The design

  • A queue-decoupled pipeline: frontend → FastAPI backend → a Firestore job queue → a Colab GPU worker running the model → back to the user.
  • The backend stays light — it enqueues a job and waits; the heavy LLM inference runs on separate GPU hardware and writes results back.
  • Handles PDF upload → text extraction → chunking → grading → a structured evaluation.

Context

  • Built within Level Up, a two-year honors program for outstanding students.
  • Part of a CS degree completed with a 93 GPA.
